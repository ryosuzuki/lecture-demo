Text → tokens → embeddings, together

The sentence, token IDs, embedding table, and vector stay visible in one linked 3D view. No tab switch is needed.

A 7-minute introduction following 3Blue1Brown’s text → tokens → vectors overview and embedding-column explanation. The new interactions are extensions, not shot-for-shot replicas.

1. Predict the token boundaries · 2 minutes

Open Tokenize text. Before expanding, ask: “How many tokens do you expect in this sentence?” Press Animate to trace the selected token’s path into its embedding. GPT-2 splits roamed into ␠ro / amed and verdant into ␠ver / d / ant. Spaces and punctuation matter. Click pieces to inspect their integer IDs.

Say: “The tokenizer uses a fixed vocabulary and merge rules. It does not understand the sentence. An ID is an address, not a number measuring meaning.” Custom text is supported up to 16 tokens.

2. Select one learned column · 2 minutes

Stay on the same screen and select a token in the top row. Its ID selects a column of W_E. Follow the highlighted connector to its vector. Read the numeric components in the side panel and inspect all 768 components.

Say: “These are pretrained GPT-2-small weights, not invented values. Training learned this table. Inference just looks up a column. We display W_E as 768 × 50,257 to match the video; the downloaded tensor stores the transpose.”

3. Same token, different position · 2 minutes

Choose bank bank bank. Compare positions 1 and 2: both are ID 3331, with identical token embeddings. Position 0 is different because it has no leading space. Turn Add position ON and compare positions 1 and 2 again.

Ask: “What changed, and what stayed fixed?” The token embedding stayed fixed; the learned position vector changed. GPT-2 adds them before its Transformer blocks. Position addition is not yet contextual understanding.

4. Meaning needs context · 1 minute

Compare A machine learning model with A fashion model. The final token has the same ID and token embedding. Later attention layers can update its representation using different context. Continue to Inside the Transformer.

Transition boundary: the existing attention views preserve the source’s simplified eight-word example and illustrative activations. They do not execute GPT-2 on the tokens from the new input views. The source also simplifies tokenization to words for those explanations.

What is real, and what is a view?

  • Real: GPT-2 byte-level BPE token IDs and lossless full-sequence decoding.
  • Real: 25 pretrained 768D token embeddings and the first 16 learned position embeddings. These cover all presets. Other token vectors are explicitly unavailable, never synthesized.
  • View: only 8 numeric components are shown in the matrix and 3 in the spatial arrows. The axes are component indices, not “meaning”, “gender”, or “sentiment”. This is not the entire embedding geometry.
  • GPT-2-small has 768 dimensions. The source discusses GPT-3 with 12,288 dimensions. Do not interchange these numbers.
