Slide 69 · Where queries come from

Open 3 · Where queries come from. Select creature. Read x and W_Q, then q = W_Q x. Select blue: it has its own query as well as a key and value. One head does not mean one query for the whole sentence.

Ask: “For eight tokens and one head, how many query vectors do we calculate?” Answer: eight. Twelve heads give 96 vectors per layer; 96 heads give 768. The same W_Q is shared across positions within a head, but heads have separate learned projection parameters. During cached one-token generation, only one new query per head is computed; cached keys and values cover earlier tokens.

“Any adjectives before me?” is a human interpretation, not a text question stored inside the model. Heads can learn previous-token, grammatical, or entity-reference patterns, but there is no fixed catalog of named query types and a head need not have one clean role.

Slides 70–73 · One complete attention calculation

Open 4 · Single-head attention. Keep creature as receiver and blue as source. Two independent 3D views sit side by side on the same page: Q/K matching on the left, and the Value sum on the right. Rotate either without moving the other. The readable HTML calculation table is below; it never rotates.

  1. Read q = [2, 2, 0.2] and k_blue = [0, 2, 0]. Their dot product is 4.
  2. Divide by √3 because this teaching head has three query/key components: 4 / √3 ≈ 2.309.
  3. Mask future positions to −∞. Roamed is excluded when updating creature.
  4. Apply softmax across the allowed sources. The displayed exponentials subtract the maximum for numerical stability; this leaves the softmax unchanged. Blue receives about 0.449.
  5. Multiply that weight by v_blue. Sum ALL weighted values, then apply W_O. We use W_O = I, so the projection is explicit but does not change z.
  6. Add the update to the input: x′ = x + W_O z. Animate to connect the weighted arrows tip to tail.

Interventions: change Q projection and watch the weights and endpoint move. Reset; change the blue key projection and compare. Reset; change only the blue Value strength: the attention weights stay fixed but the endpoint moves. The sliders change shared projection-matrix entries, not a single unexplained score.

Slides 74–75 · Multiple heads

Open 5 · Multiple heads. Each head uses its own Q/K/V projections and contributes to the combined update. Its plane has a query for every token. The additional displayed patterns are illustrative, not measured GPT-3 attention maps.

Keep model scales distinct

  • New calculation view: deliberately chosen 3D inputs and matrices; every step is computed exactly. Layer normalization, biases, dropout, and the MLP are omitted.
  • GPT-2-small: 768 embedding components, 12 heads, 64 query/key components per head.
  • GPT-3 175B, as discussed by 3Blue1Brown: 12,288 embedding components, 96 heads, 128 query/key components per head.
  • The source’s simplified adjective example does not prove that a real head adds exact word meanings. Updated vectors are not exact phrase embeddings.
