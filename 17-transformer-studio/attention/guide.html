This 14-chapter lesson covers the main conceptual and computational arc of 3Blue1Brown: Attention in transformers, visually explained. Allow 35–45 minutes with student predictions, or use chapters 3–9 as a 20-minute core.

Start here

  2. Chapter 8: turn the mask off, inspect future weights, then restore it.

  4. Chapter 12: disable heads and compare the two equivalent output calculations.

Offline use

Unzip the site, open a terminal in that folder, run python3 -m http.server 8000, and open http://localhost:8000. Three.js is bundled locally. No model API, external fonts, or login is required. Browser module security means double-clicking index.html is not sufficient.

What is and is not reproduced

The reference's full available English captions were read, with representative frames spanning the chapter inspected. This is not a claim of continuous full-video viewing or direct full-audio listening. It is an original interactive explanation of the chapter's mechanisms, not a frame-for-frame reconstruction, copied narration, or identical 3D artwork.

Context illustrations are schematic. The main numerical example uses eight words, 4-dimensional inputs, 2-dimensional heads, and three hand-designed heads. Position is an explicit fourth feature; the 3D geometry draws only the first three. A toy positional feature does not implement a reliable nearest-adjective rule. Actual learned heads need not have these semantic roles. Cross-attention uses a separate hand-designed example. The final Transformer stack is schematic: MLP, normalization, training, and text generation are explained but not numerically simulated.

The site's attention matrices use receiving Queries as rows and source Keys as columns, transposed from the video's main diagram. All relevant row sums equal one. The optional attention temperature and direct Query/Value interventions are added experiments, not claims about a standard GPT interface.

Verification

Independent arithmetic checks cover softmax normalization, score scaling, causal zeros, weighted sums, residual addition, Value intervention invariance, output-projection equivalence, and GPT-3 projection parameter counts. Browser QA covers all 14 chapters at desktop, 390px and 320px widths; direct Query dragging, sliders, masks, head switches, explanations and scene scrubbing. Physical phones and Safari are not covered.

1. One word. Several meanings.

Explain afterward: The token embedding stays the same. Different context can produce different updates. Position information is separate from the token lookup.

2. Build a more specific tower.

Say: Eiffel can make a generic tower more specific. Miniature can then change its implied scale. Farther through a model, vectors may encode much richer information than these simple attributes.

Ask before touching: Enable Eiffel, then miniature. Can a second update change a different property?

Operate: eiffel, miniature. Rotate the scene if useful; use Build this scene to assemble the visual step by step.

Explain afterward: Yes. Updates are vectors, not replacement dictionary definitions. Here one changes identity and another reduces a size coordinate. The two controls illustrate the desired behavior, not a learned attention computation.

3. Words become vectors — with position.

Open interactive chapter · 3Blue1Brown at 4:29

Say: A fluffy blue creature roamed the verdant forest. Each token gets an input vector. We use 4 dimensions: two illustrative descriptor features, a noun feature, and a position feature. Only the first three are spatial coordinates; position is shown numerically.

Ask before touching: Select creature and forest. Turn position strength to zero. Can this toy distinguish their input vectors now?

Operate: tokens, pos. Rotate the scene if useful; use Build this scene to assemble the visual step by step.

Explain afterward: No. We deliberately gave the two nouns the same content features. With position disabled their inputs are identical. Real models have different token embeddings and richer position encodings.

4. One input, three learned projections.

Open interactive chapter · 3Blue1Brown at 6:14

Say: A Query describes what a receiving token seeks. A Key describes what a source can match. A Value supplies the content to transfer. The same projection matrices are applied to every token; they are model parameters, while Q, K, and V depend on the input.

Ask before touching: Change the selected token. Which things change: the projection matrices, the projected vectors, or both?

Operate: tokens, head. Rotate the scene if useful; use Build this scene to assemble the visual step by step.

Explain afterward: Only the projected vectors change. The matrices are shared across tokens. Real weights are learned; the small weights here are hand-designed to illustrate the adjective-to-noun story.

5. Alignment becomes a dot product.

Open interactive chapter · 3Blue1Brown at 8:07

Say: Drag the gold Query tip in the plane, or use the two sliders. Teal Keys remain fixed. This directly intervenes on one Query after projection; it does not retrain the model. The exact dot products below update as you move.

Ask before touching: Aim Q toward fluffy, then blue, then the opposite direction. Can a raw score be negative?

Operate: qx, qy, tokens. Rotate the scene if useful; use Build this scene to assemble the visual step by step.

Explain afterward: Yes. Opposite directions can produce negative dot products. Scores are not probabilities. Increasing length can also increase a dot product without changing direction.

6. Every Query meets every Key.

Open interactive chapter · 3Blue1Brown at 8:31

Say: Each row is a receiving Query; each column is a source Key. Click a cell in the table or a 3D bar to inspect that pair. A larger positive bar means a stronger raw match. Negative scores extend below the plane.

Ask before touching: Compare the creature and forest rows. Why does a high raw score not necessarily mean information can flow?

Operate: tokens, head. Rotate the scene if useful; use Build this scene to assemble the visual step by step.

Explain afterward: Raw compatibility is only the first step. A causal mask can forbid a future source even if its score is high, and softmax determines its relative share.

7. Scores become a distribution.

Open interactive chapter · 3Blue1Brown at 9:15

Say: Exponentiate the scores and divide by their sum. Subtracting the largest logit m keeps the computation numerically stable without changing the answer. Our optional temperature control changes sharpness; it is an experiment, not an extra required GPT parameter.

Ask before touching: Lower temperature. Do all scores increase, or does the distribution become more concentrated?

Operate: temp, tokens, head. Rotate the scene if useful; use Build this scene to assemble the visual step by step.

Explain afterward: The logits are rescaled and the largest ones gain relative probability. The normalized weights still sum to one. This is attention temperature, not the sampling temperature used to select a generated token.

8. Do not leak the answer.

Open interactive chapter · 3Blue1Brown at 10:50

Say: Training can predict the next token at every position at once. A future token would reveal an answer, so its logit is set to negative infinity BEFORE softmax. The remaining weights are renormalized. The diagonal is allowed.

Ask before touching: Select creature. Toggle the mask off. Can it now read verdant and forest? Restore the mask and check the row sum.

Operate: tokens, mask, temp. Rotate the scene if useful; use Build this scene to assemble the visual step by step.

Explain afterward: With the mask off, future tokens can receive weight. With it on, every future weight is exactly zero and the row still sums to one. Zeroing weights after softmax without renormalizing would be wrong.

9. Values carry the actual information.

Open interactive chapter · 3Blue1Brown at 13:10

Say: The colored arrows are weighted Value contributions, placed head-to-tail from the white original vector. The coral arrow ends at the updated representation. Scrub the scene to assemble the sum. The 4th coordinate is preserved but not drawn as a spatial axis.

Ask before touching: Set fluffy Value gain to zero, then negative. Do the attention weights change?

Operate: gain, tokens, head. Rotate the scene if useful; use Build this scene to assemble the visual step by step.

Explain afterward: No. Q and K determine the attention pattern; this intervention changes only the fluffy Value. The weighted update changes, but A does not. It changes that source Value for all receivers in the selected head.

10. A large update through a narrow channel.

Open interactive chapter · 3Blue1Brown at 16:08

Say: Instead of one large square value map per head, factor it into two narrower matrices. Their product has rank at most the head dimension. “Up” does not invert “down”: it creates an update, not a reconstruction of the entire input.

Ask before touching: Select creature, then fluffy. Is the lifted Value equal to the original input?

Operate: tokens, head. Rotate the scene if useful; use Build this scene to assemble the visual step by step.

Explain afterward: Usually not. Here creature’s content does not create a Value update, while fluffy does. The position and noun coordinates are discarded by this Value map. Low rank limits the subspace of possible updates.

11. Queries can come from a different stream.

Open interactive chapter · 3Blue1Brown at 18:20

Say: In translation, a partial target sentence can query a source sentence. This small two-query / three-source example illustrates the rectangular attention matrix. Keys AND Values come from the source, Queries from the target. The illustrated weights are not learned translations.

Ask before touching: Move target Query 1 with the sliders. Does Query 2 change too?

Operate: qx, qy. Rotate the scene if useful; use Build this scene to assemble the visual step by step.

Explain afterward: No. Each query has its own normalized distribution over the source. The matrix is 2×3, not necessarily square. An encoder–decoder source stream usually needs no causal future mask here, though other masks can still apply.

12. Several heads propose different updates.

Open interactive chapter · 3Blue1Brown at 19:20

Say: Each head has its own Q, K, and Value maps. The example heads favor descriptors differently. Enable and disable them to inspect their contributions. The output matrix combines their concatenated low-dimensional results before the residual addition.

Ask before touching: Disable one head. Does the result equal the sum of the remaining heads? Compare sum and concat calculations below.

Operate: heads, tokens. Rotate the scene if useful; use Build this scene to assemble the visual step by step.

Explain afterward: Yes, exactly up to floating-point rounding. Stacking the per-head up matrices into WO makes concatenation-plus-projection algebraically identical to summing each projected head output.

13. Count the cost of attention.

Open interactive chapter · 3Blue1Brown at 22:03

Say: A dense attention pattern has n² entries per head. Doubling the context quadruples the pair count, but does not add learned projection parameters. GPT-3’s largest configuration used d=12,288, dₖ=128, 96 heads, and 96 layers.

Ask before touching: Double context length. Then double layers. Which changes the pair count, and which changes learned parameters?

Operate: contextSize, layers. Rotate the scene if useful; use Build this scene to assemble the visual step by step.

Explain afterward: Context length changes the number of pairs. Layer count changes the number of distinct parameter sets. The count here excludes biases, normalization, embeddings, and MLPs. Memory-efficient kernels need not materialize the entire n² matrix.

14. Contextualize, then contextualize again.

Open interactive chapter · 3Blue1Brown at 23:19

Say: Attention mixes information across positions; MLPs transform each position’s representation. Transformers repeat both, with residual connections and normalization. The final position is read out to predict the next token. This scene is architectural, not a numerical GPT simulation.

Ask before touching: Move through the stack. Why can the final vector represent more than the last word alone?

Operate: depth. Rotate the scene if useful; use Build this scene to assemble the visual step by step.

Explain afterward: Repeated attention can bring relevant context into that position, including information already combined elsewhere. The last vector can support next-token prediction. Parallel matrix operations make the architecture efficient to train at scale.

Exit questions

  1. What can change a Value without changing the attention pattern in our intervention? What would happen if we changed the original input instead?
  2. Why mask logits before softmax rather than zero probabilities afterward?
  3. Why does doubling context length not double the number of model parameters?
